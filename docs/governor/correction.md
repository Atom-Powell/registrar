Every entry in a validation report carries a `checkId`. Find it here. The report's own `remediation` field is phrased as an instruction you can execute; this catalogue tells you what rule produced it and where that rule comes from.

A failed check is not a bug to argue with. Fix the exact field the report names, change nothing else, and resubmit.

| `QA-ENG-06` | input | ConfigurationError | Every dataInputs.sections[].blocks[].blockType is one this engine version renders: paragraph, h2, h3, bulletList, table, clauseInsertion, radioQuestion, warnCallout, aggregationTable, copyReadyMessage. | `QA-ENG-07` | content | not set | Body-prose blocks (paragraph, h2, h3, bulletList, table) contain no unresolved bracketed placeholder tokens. QA-SPEC-07 inspects only placeholderMap and QA-SF-08 only prohibited characters, so neither catches this. Blocks in draft and promotion. |
| `QA-ENG-08` | input | MetadataViolation | artifactIdentity.layer matches the framework layer configured for the artifact type in artifact-types.json. Before this check, layer was the one required identity field the engine accepted on trust: it flows into artifact-manifest.json and nothing else validated it. Types with no configured layer are skipped because QA-ENG-02 already refuses them. Blocks in draft and promotion. |
